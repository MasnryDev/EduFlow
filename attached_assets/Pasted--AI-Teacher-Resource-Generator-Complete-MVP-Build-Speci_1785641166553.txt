# AI Teacher Resource Generator – Complete MVP Build Specification
Everything you do, you must pull and push changes to a new github repo that you will create called AI_Teaching_Resource_Generator. 


Build a modern, professional SaaS web application called **AI Teacher Resource Generator**. The goal of this application is to help teachers create high-quality teaching resources in under one minute using AI. This is an MVP (Minimum Viable Product), so focus on creating a polished, reliable, and scalable foundation. Do **not** implement subscription plans, payment processing, or credit limits in this version. However, structure the project so Stripe can be integrated easily later, and include detailed instructions in the README explaining where and how Stripe should be added in the future.

The application should be built using **Next.js (App Router)** with **TypeScript**, **React**, and **Tailwind CSS**. Use **shadcn/ui** for reusable UI components, **Lucide React** for icons, **Supabase** for authentication and database storage, **OpenAI's Responses API** for AI generation, and **Vercel** for deployment. Organize the project using clean, scalable architecture with reusable components, utility functions, API routes, and server actions where appropriate. Follow modern coding practices, strong typing, proper error handling, loading states, and responsive design throughout the application.

The overall design should feel clean, modern, minimal, and professional, similar to Linear, Notion, or Vercel. Use rounded cards, subtle shadows, smooth transitions, generous spacing, and a neutral colour palette with one primary accent colour. Ensure the website works perfectly on desktop, tablet, and mobile devices. Include dark mode support using next-themes.

The application should contain the following pages:

**Landing Page:** Create a professional marketing homepage with a hero section containing a headline such as "Create Professional Teaching Resources in Under 60 Seconds", a supporting description, and a primary call-to-action button leading to sign-up. Below the hero, include a features section highlighting Lesson Plans, Worksheets, PowerPoint Outlines, Classroom Activities, Assessments, and Curriculum Planners. Add a section explaining how the application works in three simple steps: choose resource type, enter lesson details, generate instantly. Include testimonials using placeholder content, a FAQ section, and a professional footer with navigation links.

**Authentication:** Implement secure authentication using Supabase Auth. Support email/password registration, login, password reset, and Google sign-in if easily configurable. Protect all authenticated routes so only logged-in users can access the dashboard and generation features.

**Dashboard:** After login, users should be redirected to a dashboard displaying a welcome message, a "Create New Resource" button, recently generated resources, quick statistics (such as total resources created), and navigation links. Build the dashboard using reusable cards and a sidebar navigation containing Dashboard, Create Resource, History, Templates (placeholder), and Account.

**Create Resource Page:** This is the core feature of the application. Build a clean form that allows teachers to generate teaching resources. The form should include a dropdown for Resource Type with the following options: Lesson Plan, Worksheet, Assessment, Classroom Activity, PowerPoint Outline, and Curriculum Planner. Include dropdowns or searchable selects for Subject and Year Level, text inputs for Topic and Learning Objectives, a duration selector, a difficulty selector, and a large optional textarea for additional instructions. Validate all required fields before submission. Display loading indicators while generation is in progress.

When the teacher submits the form, send the request to a secure Next.js API route. Construct a structured prompt that instructs OpenAI to behave as an experienced Australian teacher aligned with the Australian Curriculum Version 9. The prompt should include all user selections and request clearly structured output with appropriate headings depending on the resource type. Use the OpenAI Responses API rather than older completion endpoints. Store API keys securely in environment variables and never expose them to the client.

After generation, display the AI response in a clean editor-like interface with headings, spacing, and formatting preserved. Provide buttons to Copy to Clipboard, Regenerate, Save, Download as PDF, and Download as DOCX. The Regenerate button should rerun the request using the same form values. The Save button should persist the resource to the database.

**History Page:** Build a searchable history page showing every previously generated resource for the logged-in user. Display the resource title, resource type, subject, year level, topic, and creation date. Allow users to open, view, duplicate, or delete saved resources. Use pagination or infinite scrolling if necessary.

**Account Page:** Build a simple account management page showing the user's profile information, email address, display name, account creation date, and authentication settings. Include placeholders where future subscription information will eventually appear, but do not implement billing functionality.

Use Supabase as the backend database. Create a `profiles` table containing the authenticated user's information, and a `resources` table containing generated teaching resources. The resources table should include fields such as id, user_id, title, resource_type, subject, year_level, topic, learning_objectives, duration, difficulty, additional_instructions, prompt, ai_response, created_at, and updated_at. Ensure Row Level Security (RLS) is enabled so users can only access their own resources.

Create reusable React components wherever possible. At minimum, include reusable components for the sidebar, navigation bar, page header, dashboard cards, generation form, loading spinner, resource viewer, resource history cards, confirmation dialogs, buttons, modals, alerts, and empty states. Keep business logic separate from presentation logic.

Implement comprehensive error handling. Display friendly error messages if AI generation fails, Supabase is unavailable, or authentication expires. Prevent duplicate submissions while generation is running. Ensure all API routes validate incoming data before processing requests.

Use environment variables for all secrets, including the Supabase URL, Supabase anonymous key, Supabase service role key if required, and the OpenAI API key. Never hardcode secrets anywhere in the project.

Write clean documentation throughout the project. Add comments only where logic is genuinely complex. Follow consistent naming conventions and folder structures. Include a comprehensive README that explains project setup, installation, local development, environment variables, Supabase configuration, deployment to Vercel, database schema, authentication setup, AI configuration, troubleshooting, and future roadmap.

In the README, include a dedicated section titled **"Future Stripe Integration"**. Explain that payments have intentionally been excluded from the MVP but the application has been designed to support them. Describe, at a high level, how Stripe should later be integrated by installing the Stripe SDK, creating Products and Prices in the Stripe Dashboard, storing Stripe Customer IDs and Subscription IDs in Supabase, creating checkout sessions and a customer billing portal, listening to Stripe webhooks to synchronise subscription status, protecting premium routes using subscription state, and deploying the required environment variables (`STRIPE_SECRET_KEY`, `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`, `STRIPE_WEBHOOK_SECRET`, and Price IDs). Clearly indicate where these files would likely be added (e.g. `/lib/stripe.ts`, `/app/api/stripe/checkout`, `/app/api/stripe/webhook`, middleware for access control, and updates to the database schema).

The finished project should compile without errors, use strict TypeScript, follow ESLint recommendations, and be production-ready. The codebase should prioritise maintainability, readability, modularity, accessibility, and future scalability over quick shortcuts. Every major feature should be implemented as if this project will eventually become a commercial SaaS product used by thousands of teachers.
